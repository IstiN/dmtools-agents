# Note: n_0004_c508

Local verification of the CRAP quality gate (.github/workflows/quality.yml) has two gotchas: (1) the crap4js bin symlink never triggers main() (its `import.meta.url === process.argv[1]` check fails through node_modules/.bin), so run it via `node --input-type=module -e "import { main } from '<tools>/crap4js/src/cli.js'; main(['js', '--coverage', <cov.json>, '--threshold', '4879.8'])"`; (2) Istanbul coverage keys are the ORIGINAL repo's absolute paths (nyc instrument embeds them), so crap4js must be analyzed from the repo root (`js` path) for coverage to match — analyzing the instrumented copy gives Max CRAP 0.0 with all N/A (false pass). Pre-change repo max: 4475.3 (js/common/scm.js _createAdoProvider), ratchet 4879.8. Also: `dmtools run` locally enforces only the base-12 cli_execute_command whitelist (ansible, aws, az, dmtools, docker, gcloud, gh, git, kubectl, npm, terraform, yarn — no bash); job-level envVariables.CLI_ALLOWED_COMMANDS is NOT applied by `dmtools run`, but the process env var IS read, so `CLI_ALLOWED_COMMANDS=bash dmtools run <cfg>` enables bash-dependent tests.
